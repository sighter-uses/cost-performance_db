# 集めた知識と、そこから決まること

2026-09-04 調査。この分野は情報の質が極端に低く、情報商材への誘導と
数字のない一般論が大半を占める。**実測値・再現手順のあるものだけを採用**し、
根拠のない主張は載せていない。「調べたが使えなかった」ものも記録する ——
同じ軸をまた調べ直さないため。

## 1. 前提が変わっている — AI Overviews

| 事実 | 出典の性質 |
|---|---|
| 2026年3月時点で**全検索クエリの約48%**にAI Overviewsが表示（2025年12月は34.5%） | 計測値 |

1. **AIの回答内で引用されている割合**

3. **第三者からの言及（サイテーション）**

## 2. AIが情報源を選ぶ6つの基準

これが今回いちばん重要な収穫。**満たすべき条件が具体的**で、しかも
一般的なアフィリエイトブログには満たせず、**我々には満たせる**。

| 基準 | 中身 |
|---|---|
| **到達可能性** | AIがページをクロール・読み取れる状態か |
| **関連性** | ユーザーの質問と回答内容の一致度 |
| **根拠性** | 主張を裏付けるデータ・出典が明示されているか |
| **信頼性** | 著者・組織の専門性が示されているか（E-E-A-T） |
| **鮮度** | 情報の最新性と定期更新の有無 |
| **使いやすさ** | AI回答にそのまま引用できる形式で書かれているか |

### 決定的な一文

> **独自調査によって「まだ世の中にない数字」をゼロから作り出すことが、AIにとっての新しい引用元になる**

これは我々のサイトの説明そのものである。純アルコール20g単価は世の中に存在しない数字で、
2,466件を集計して作っている。**AI Overviewsに殺される側ではなく、引用される側に回れる**
数少ない形をたまたま作っていた。

### データの示し方（必須3項目）

- **n数** — 母数が明示されていないデータは引用適性が大きく下がる
- **調査期間** — 「〇〇年〇月〇日〜〇月〇日実施」と具体的に
- **対象の定義** — 何を対象としたかを限定して明記

**最低基準 n=100 / 引用対象レベル n=300以上。**
我々は全体2,466件、種別ごとでも309〜386件。**全ページで引用対象レベルを超えている。**

### ページ構造でやるべきこと

- 調査概要を**ボックス形式で独立したブロック**に
- 各セクションは**1データポイント×1テーマ**で完結
- 図表には alt とキャプション
- **Article / FAQPage スキーマ**を JSON-LD で
- sitemap.xml の `lastmod` を正確に

### やっても効果が薄いこと

- 装飾優先の複雑なグラフ
- 複数の発見を1セクションに詰め込む
- **著者情報の省略**
- 調査概要なしでデータだけ掲載
- 被引用の確認をせず放置する運用

なお**構造化データの実装は優先度が比較的低い**という指摘もあった。
一次情報とE-E-A-Tのほうが効くという整理。

### 何を入れたか

- **調査概要ブロック** — 全8ページの本文冒頭に独立したボックス。
  調査主体・対象・期間・有効件数(n)・収集方法・集計方法・除外基準・既知の限界・再現性の9項目
- **著者情報** — フッターに運営者名と、**note と GitHub リポジトリへのリンク**。

  専門性の根拠にする。自己申告より検証可能性のほうが強い
- **調査期間** — 「取得日◯月◯日」から「◯月◯日〜◯月◯日（本ページの数値は◯月◯日取得分）」へ。
  スナップショットの最古の日付から自動で組み立てる。
  **期間だけ書くと、その期間の平均を出しているように読める**ので併記は必須
- **構造化データ** — `Person` / `Dataset` / `FAQPage` を追加（既存の WebSite・WebPage・

### Article を入れなかった理由

調査時のメモには「Article / FAQPage スキーマ」とあったが、**Article は入れていない。**
このページの本体は記事ではなく調査データそのものなので、型と中身が食い違う。
代わりに **`Dataset`** を使った —— 対象・測定手法・測定変数・対象期間を宣言できる型で、
我々が持っているものを正確に表す。**型を偽ると、かえって信用を落とす。**

## 4. サイテーション（第三者からの言及）

- サイテーションは**リンクなしの言及**。被リンクとは別物で、役割は知名度・ブランド認知
- 独自の調査・統計データはプレスリリースやレポートとして公開すると自然な被リンクを生む
- **ただしプレスリリース経由の被リンクはほとんど nofollow**

これも我々の形と噛み合う。データを持っていることが、言及される理由になる。

## 5. 一般論の検証 —— 満たしているかを実測する

順序が逆で、**一般論すら満たせていないなら、その時点で価値がない。**
目新しさは採否の基準ではなく、**満たしているかどうかだけが基準**である。

そこで、一般論として挙がっていた項目を実際に自分たちに当てて測った。

## 6. この調査から導かれる方針

**主戦場を「順位」から「引用」に置き換える。**

一般的なアフィリエイトブログは、AI Overviewsに要約されて流入を失う側にいる。
我々は一次データを持っているので、**引用される側**に回れる。しかもその条件は
明文化されていて、我々は6基準中6項目を満たしており、残り4項目も一度の作業で埋まる。

これは週5時間の制約とも噛み合う。**記事を毎回書くのは介入が毎回発生するが、
引用される条件を満たすのは一度で終わる。**

ただし正直に書いておくと：

- **引用されるまでの期間は誰も明示していない。** 数ヶ月かかると見るべき
- **引用されても収益に直結するとは限らない。** AIの回答内で名前が出ても、
  クリックされなければアフィリエイト収益はゼロ。ここは検証されていない
- 上の調査は「引用されやすくなる条件」であって「引用される保証」ではない

### やめること

- はてブ攻略。**満たすべき具体項目が公開されていない**ので、
  検証も改善もできない。手を出す根拠がない

初回はここに「ノウハウの追加収集をやめる」と書いたが、これは誤りだった。
**「ノウハウコレクター」とは、集めるだけで実行に移さない状態を指す。**
すでに実装し、公開し、投稿している我々が、さらに改善策を探すのは
性質がまったく違う。**調べることと動かないことを混同していた。**
やめるべきは「調べること」ではなく「調べただけで終えること」。

### 順序

1. **6基準の穴4つを埋める** —— 2026-09-08 完了（著者情報・調査概要ブロック・
   調査期間の形式・構造化データ）。ついでに一般論側の未対応も1つ潰した（サイト→noteの導線）
2. **note プロフィールを整える** —— アイコン・ヘッダー・サイトURL。あなたの作業
3. PLAN.md の記事を書き始める（指名検索とサイテーションの土台）。
   書く前にキーワードから逆算する工程を一度入れる
4. 1ヶ月後、Search Console で「引用されているか」を確認して方針を見直す
